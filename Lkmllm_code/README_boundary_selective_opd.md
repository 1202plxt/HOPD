# 基于边界误差的时间戳选择性蒸馏

本方法针对视频时序定位：学生根据完整视频和文本查询预测事件区间 `[start, end]`。训练时，冻结教师获得额外的 GT 证据片段。我们分别比较师生起点、终点与真实标注的误差，只对教师更准确的边界进行 token 级蒸馏。

## 为什么要分别选择两个边界

整体 IoU 衡量预测区间与标注区间的重叠情况。教师的 IoU 比学生高，并不意味着教师的起点和终点都更准确。如果无差别地蒸馏整条答案，学生原本较准确的一个边界也可能受到较差教师输出的影响。

因此，样本筛选依据是**各边界到对应 GT 边界的绝对误差**，而不是教师预测点是否落在 GT 区间内部。教师整体 IoU 作为分析指标记录，不作为本方法的必要门控条件。

## 边界选择规则

设真实区间为 `[s_g, e_g]`，学生预测为 `[s_s, e_s]`，教师预测为 `[s_t, e_t]`，分别计算：

```text
起点收益 = |s_s - s_g| - |s_t - s_g|
终点收益 = |e_s - e_g| - |e_t - e_g|
```

当某个边界的收益**严格大于**容差 `epsilon` 时，选择该边界进行蒸馏。`epsilon` 的单位是秒，默认值为 `0`：教师必须严格更准确，误差相等不选中。

| 起点比较 | 终点比较 | 时间数字 token 的蒸馏范围 |
| --- | --- | --- |
| 教师更准 | 教师更准 | 起点和终点 |
| 教师更准 | 学生更准或误差接近 | 仅起点 |
| 学生更准或误差接近 | 教师更准 | 仅终点 |
| 学生两个边界都更准或误差接近 | — | 不进行边界蒸馏，跳过样本 |

### 例子：教师落在 GT 内部

GT 为 `[10, 20]` 秒，学生预测 `[9, 24]`，教师预测 `[12, 19]`。

- 起点误差：学生 1 秒，教师 2 秒。教师起点虽然落在 GT 内部，但比学生更不准，因此不蒸馏起点。
- 终点误差：学生 4 秒，教师 1 秒。教师终点更准，因此蒸馏终点。

### 例子：两个教师边界都值得学习

GT 为 `[10, 20]` 秒，学生预测 `[7, 24]`，教师预测 `[11, 19]`。教师起点、终点误差都是 1 秒，分别小于学生的 3 秒、4 秒，因此选择两个边界。

## token 级损失

1. 学生根据普通视频和查询生成一条回答。
2. 教师根据特权输入独立生成回答，用师生预测与训练 GT 计算各边界误差。
3. 在学生实际生成的 token 序列中定位起点和终点数字；一个数字可能对应多个 token。
4. 对选中边界的每个数字 token，使用冻结教师对**同一条学生前缀**重新评分，计算完整词表的 `KL(student || teacher)`。
5. 对选中的数字 token 损失取平均，然后反向传播到选中 head 的 Q/O 低秩参数。

当前版本的非时间数字 token 权重为 0；未选中的另一边界也没有直接损失。两个边界仍共享模型参数，因此更新一个边界可能间接改变另一个边界的表现，需要通过独立评测判断。

教师在自身生成答案中某个边界更准确，并不保证它在学生已有前缀下提供的分布一定能改善学生。因此，边界误差门控是需要验证的训练策略，不是效果保证。

## 无效样本及日志

- 师生任一预测解析无效时，跳过该样本的边界蒸馏。
- 当前实现只处理 `The event happens in <start> - <end> seconds.` 格式；无法可靠映射数字到生成 token、或起点与终点共享 token 时跳过并记录原因。
- 日志记录师生预测、IoU、两个边界的误差收益、选择结果和 token 索引；IoU 仅用于分析。
- GT 在训练阶段用于构造教师证据片段和比较误差；学生独立测评只输入普通视频与查询。

## 启用方式和实验状态

现有八卡 DP4/MP2 训练入口新增可选参数：

```text
--boundary-selective --boundary-epsilon 0
```

不传 `--boundary-selective` 时沿用原整段 OPD 流程。该方法基于冻结的 32B 教师、Qwen3 学生及预选 head；修改沿用原入口的硬件与视频输入设置。初步 CPU 逻辑测试通过，真实 tokenizer、GPU 前向与反向、分布式训练以及下游指标仍需验证。请先冒烟，再与同协议的原模型和整段蒸馏进行对比。
